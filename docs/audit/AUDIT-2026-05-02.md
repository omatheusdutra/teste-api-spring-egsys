# Auditoria pre-playground - 2026-05-02

## Status

Documento histórico. Este arquivo registra o estado do repositório antes da implementação do playground e do pentest
defensivo. Ele não deve ser lido como documentação atual do sistema.

Documentação atual:

- Visão geral e execução: [README.md](../../README.md)
- Playground controlado por propriedades: [ADR 0009](../adr/0009-playground-production-demo-controlled.md)
- Pentest defensivo: [docs/pentest/REPORT-2026-05-02.md](../pentest/REPORT-2026-05-02.md)
- Manual dos scripts: [tools/pentest/README.md](../../tools/pentest/README.md)

## Snapshot Encontrado

Na auditoria read-only inicial foram verificados:

- endpoints REST de auth, categorias, tarefas, histórico, CSV e actuator;
- DTOs com `@JsonIgnoreProperties(ignoreUnknown = false)`;
- `SecurityConfig` com CSRF desabilitado para API stateless, CORS configurável, headers de segurança e sessão stateless;
- JWT RS256, Argon2id, Redis para revogação/rate limiting e ProblemDetail para erros;
- testes de segurança cobrindo autenticação, autorização, IDOR, mass assignment, SQLi, XSS, XXE, SSRF, brute force,
  timing attack, information leak, supply chain e outros cenários;
- ausência inicial de playground.

## Lacunas Que Motivaram a Fase

| Lacuna inicial | Resultado atual |
| --- | --- |
| Não havia `/playground` | Implementado e servido por controller dedicado |
| Não havia decisão arquitetural do playground | ADR 0008 criada e depois substituída pela ADR 0009 |
| Não havia pentest reproduzível via script | Scripts em `tools/pentest/` cobrem 49 cenários |
| Não havia separação entre demo e ataques interativos | `egsys.playground.enabled` e `egsys.playground.attack-demos-enabled` |

## Observação

Algumas decisões planejadas neste snapshot foram intencionalmente substituídas durante a implementação. A decisão vigente
é a ADR 0009: playground disponível como demo controlada e demonstrações ofensivas habilitadas apenas em ambiente
controlado.

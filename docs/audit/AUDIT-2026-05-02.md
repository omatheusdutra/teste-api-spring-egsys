malformado nao chega ao controller (404 limpo).

### DTOs de request

Todos com `@JsonIgnoreProperties(ignoreUnknown = false)` — ou seja, qualquer campo extra causa
`HttpMessageNotReadableException` e vira `400`. Excelente blindagem contra mass assignment.

| DTO | Campos | Validacoes |
| --- | --- | --- |
| `RegisterRequest` | `email`, `password` | `@Email`, `@NotBlank`, `@Size(min=12,max=128)` na senha |
| `LoginRequest` | `email`, `password` | `@Email`, `@NotBlank`, `@Size(max=128)` |
| `RefreshRequest` | `refreshToken` | `@NotBlank`, `@Size(max=512)` |
| `CriarTarefaRequest` | `titulo`, `descricao`, `categoriaId`, `dataHora` | `@NotBlank` titulo (max 200), descricao max 2000, `@NotNull` categoria, `@FutureOrPresent` dataHora |
| `AtualizarTarefaRequest` | idem `CriarTarefaRequest` | idem |

Nenhum DTO de request expoe `ownerId`, `role`, `id` ou `criadaEm`. O `ownerId` e sempre derivado
do `SecurityContext` via `currentUserId()`.

### Configuracao de seguranca

`SecurityConfig` (filterChain unico):

- CSRF desativado (API stateless com JWT em header).
- CORS controlado por `egsys.security.allowed-origins` (vazio em local; setado por env em prod).
- Sessao `STATELESS`.
- Headers ja aplicados a TODAS as respostas:
  - `Content-Security-Policy` restritivo (default-src 'none'; script-src 'self'; style-src 'self' 'unsafe-inline'; img-src 'self' data:; font-src 'self' data:; connect-src 'self'; base-uri 'none'; form-action 'none'; frame-ancestors 'none').
  - `Strict-Transport-Security` (1 ano, includeSubDomains, preload).
  - `X-Frame-Options: DENY`.
  - `Referrer-Policy: no-referrer`.
  - `Permissions-Policy: geolocation=(), microphone=(), camera=()`.
  - `Cache-Control` default seguro.
- `server.server-header:` vazio em `application.yml` -> banner Server omitido.
- Filtros: `JwtAuthenticationFilter` antes de `UsernamePasswordAuthenticationFilter`,
  `RateLimitingFilter` apos o JWT.
- `Argon2PasswordEncoder(16, 32, 1, 65_536, 3)` para senhas.
- Erros 401/403 voltam como `application/problem+json` via `ProblemDetail` sem stack trace.
- `JwtService` (RS256) — confirma a defesa anti-`alg=none`/HS256 nos testes.

## Decisoes para a Fase 2

1. **Profile**: criar profile `dev` distinto, herdando de `local` mas explicito — assim o
   avaliador roda com `SPRING_PROFILES_ACTIVE=dev` para liberar o playground, mas o `local`
   continua sendo o default seguro. Profiles ativos podem ser combinados (`dev,local`).

2. **Endpoints consumidos pelo playground** (todos ja existentes):
   - `POST /api/v1/auth/register`, `/login`, `/refresh`, `/logout`
   - `GET /api/v1/categorias`
   - `POST/GET/PUT/DELETE /api/v1/tarefas` + `/status/*` + `/historico`
   - Para metricas ao vivo: novo endpoint `/playground/api/metrics-summary` (so existe em dev)
     que devolve um JSON resumido derivado do `MeterRegistry`. Evita exigir role ADMIN para
     visualizar Prometheus.

3. **Rota da pagina**: `/playground` (forward para `/playground.html` servido como estatico, mas
   so quando profile `dev` esta ativo). Spring Security bloqueia a rota fora de dev.

4. **Mecanismo de protecao**: classe `PlaygroundProfileGuard` (ou bean condicional). A pagina e
   o controller sao registrados com `@Profile("dev")`. Para impedir que `playground.html` seja
   servido como recurso estatico fora de dev, vamos:
   - colocar o arquivo em `src/main/resources/playground/playground.html` (fora de `static/`),
   - servir manualmente via controller que so existe em dev,
   - adicionar um matcher de seguranca que retorna 404 para `/playground*` quando o profile dev
     nao esta ativo (defesa em profundidade).

5. **Token storage**: variavel JS em closure, nunca `localStorage`/`sessionStorage`. CSP do
   playground reutilizara a CSP global e adicionara `script-src 'self'` (ja e o caso); zero
   inline JS, zero `eval`, zero CDN externa.

6. **Mesmo design system da home**: aurora, glassmorphism, fonte Inter + JetBrains Mono, paleta
   laranja `#FF6B2C` + cyan `#22D3EE` + dark `#05070D`. Reutilizar tokens de `index.html`.

7. **ADR**: novo `docs/adr/0008-playground-dev-only.md` documentando a decisao.
